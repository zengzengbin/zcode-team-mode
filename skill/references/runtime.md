## 状态与拦截

`UserPromptSubmit` hook 识别用户消息中任一独占行的直接口令（代码块内、引用行和句子中间提到的不算），以 ZCode 提供的 `session_id` 保存状态。口令接受完整与简写形式：开启可用 `开启`/`打开`/`启动`，退出可用 `退出`/`关闭`，状态查询可用 `查看`/`查询` 搭配 `小队状态` 或 `小队模式`，`ZCode` 一词可省略（如 `打开小队模式`、`关闭小队模式`、`查看小队模式`）；对大小写和半角/全角空格不敏感。口令行必须与口令完全一致，解释、询问、引用都按普通消息处理，既不启用也不退出。任何一行的行首也会识别从 `$` 补全菜单选中本技能时 ZCode 渲染出的 Markdown 链接（其后可并列其他技能链接与任务文字），句子中间引用的链接不算。代码块内的行一律跳过。识别器未匹配的消息只写入不含原文的结构化诊断记录（`.diagnostics.jsonl`），供排查运行器实际提交内容。`PreToolUse` hook 同时检查 `Agent`、兼容 `Task` 和本技能的 `Skill` 调用。

未启用时原有子 Agent 和其他技能照常使用；新小队角色与本技能只供显式启用后使用。启用时只拒绝内置 general-purpose、Explore 和省略类型的调用（大小写不敏感），四个小队角色与文档/浏览器类专用 agent（如各 *-visual-judge、image-generator）等其他专用角色照常放行；允许的调用不返回自动批准权限，仍由原有权限系统处理。退出后恢复原有派发规则。

开启/退出口令触发状态切换的那一轮，hook 注入的上下文会要求该轮回复输出一次「👾 已开启小队模式」或「👾 已关闭小队模式」；hook 持续 active/inactive 的后续轮次注入的上下文明确要求不再输出，标记因此只出现一次。口令只改状态，不向用户复述口令内容。

注册的角色平时也会显示在列表中。状态按聊天 ID 独立、落盘保存；不会在 Stop 或任务完成时清除。恢复旧聊天能否复用相同 session ID 取决于当前 ZCode，需要实际验收；新 session ID 按新聊天默认未启用。

这是工作流约束，不是对恶意本地代码的安全沙箱。ZCode 当前运行器在 hook 脚本缺失、进程启动失败或超时后可能继续执行。程序自身可捕获的状态读取/解析错误会明确拒绝相关派发并报告，仍无法消除宿主在脚本未运行时的故障放行边界。退出口令可将本聊天状态重置为未启用；不要通过更改全局内置角色绕过故障。

精简记录仅保留时间、状态变化、角色名和允许/拒绝事件，不保存用户提示、任务正文、凭据或模型响应。

## 模型与验证

四角色通过 Markdown 前言的 `model` 和 `thoughtLevel` 绑定安装初始化时用户指定的模型与思考强度，现有 provider 配置保持原样。配置支持不等于服务端已接受，若所选模型思考档位较高（如 xhigh/max），需在实际使用中留意服务端是否支持。

用户后续如需调整模型或思考强度，可随时采用以下任一方式：
- 方式一：在 ZCode 图形设置界面中直接修改对应子智能体的模型与思考强度；
- 方式二：直接编辑目标文件 `%USERPROFILE%/.zcode/agents/team-*.md` 中的 `model:` 和 `thoughtLevel:` 字段，并同步调整 `SKILL.md` 表格。

本机适配依据为安装时的 ZCode 运行器。升级后如行为异常，应先复核 hook 注册、角色解析、模型选项和会话恢复；不要照搬其他客户端的参数。
